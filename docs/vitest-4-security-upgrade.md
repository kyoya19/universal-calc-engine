# Vitest 4 security compatibility upgrade

## Outcome

The repository test runner was upgraded from Vitest 1.6.1 to Vitest 4.1.10 to remove the development-only advisories recorded in the dependency-lock boundary.

The upgrade does not change analytical production code, package public APIs, package version, registry-publication status, or the `private: true` boundary.

## Compatibility review

The official Vitest 4 migration guidance requires Node.js 20 or newer and Vite 6 or newer. The repository CI remains on Node 20 and the validation run used Node 20.20.2.

The repository's `vitest.config.ts` only defines the test include pattern. It does not configure coverage, browser mode, custom pools, deprecated dependency inlining options, or custom environments.

Representative analytical tests use the standard `describe` / `it` / `expect` API surface. No fake-timer, snapshot, custom-runner, browser, or `vite-node` migration was required by this repository.

No test source or production source had to be changed for Vitest 4 compatibility.

## Dependency result

The lockfile was regenerated by npm tooling, not hand-edited.

The resulting key versions are:

```text
Vitest: 4.1.10
Vite: 8.2.1
vite-node: absent
esbuild: absent
@types/node: 20.19.43
TypeScript: 5.9.3
```

Vitest 4 no longer depends on `vite-node`; Vite 8's toolchain also removes the previous esbuild dependency from this lockfile.

Vite 8 requires Node.js 20.19+ or 22.12+. The CI validation runtime, Node 20.20.2, satisfies that requirement, so no Node version change was required.

## Separate CI maintenance concern

GitHub Actions currently emits a deprecation warning for the Node runtime used internally by `actions/checkout@v4` and `actions/setup-node@v4`. That warning is independent of the repository's explicit Node 20 test runtime and independent of the Vitest security upgrade. It should be handled as a separate CI-action maintenance increment.
